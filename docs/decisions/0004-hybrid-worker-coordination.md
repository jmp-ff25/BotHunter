# ADR-0004: Гибридная координация Automation Worker

Статус: принято  
Дата: 2026-08-20

## Context

Web/API должен быстро передавать Worker команды запуска, паузы
и других действий. Команда не должна теряться, если Worker временно
недоступен или процесс завершился после её получения.

Только HTTP-вызов не обеспечивает долговечность. Только периодическая
проверка БД создаёт лишнюю задержку. Celery потребовал бы broker,
result backend и дополнительную инфраструктуру, не оправданную
одним локальным Worker.

Логи не подходят для координации: у них нет атомарного claim,
acknowledgement, lease и авторитетного состояния команды.

## Decision

Использовать гибридный механизм:

1. Web/API транзакционно записывает команду с уникальным идентификатором
   в durable command inbox Operational Store.
2. После успешного commit Web/API отправляет Worker-у localhost
   HTTP signal с идентификатором команды.
3. Worker возвращает acknowledgement получения signal.
4. Worker атомарно закрепляет команду за собой на ограниченный lease.
5. Результат и состояние исполнения сохраняются в Operational Store.
6. Recovery scan находит команды, для которых signal был потерян
   или обработка прервалась.

HTTP signal является оптимизацией задержки, но не источником истины.
Acknowledgement означает получение сигнала, а не завершение команды.

Worker записывает heartbeat. В базовой архитектуре допускается только
один экземпляр Worker.

Не использовать Redis, RabbitMQ, Celery или другой broker до появления
измеренной необходимости в распределённой обработке.

## Consequences

Положительные последствия:

- команда сохраняется при недоступном Worker;
- нормальная реакция не зависит от интервала recovery scan;
- механизм работает на Windows, Linux и macOS;
- состояние легко диагностировать через Operational Store;
- отсутствуют отдельные broker и result backend.

Отрицательные последствия:

- необходимо реализовать inbox, signal endpoint, leases и recovery;
- возможна повторная доставка signal, поэтому обработчик обязан
  быть идемпотентным;
- Operational Store остаётся общей точкой отказа;
- HTTP endpoint должен быть доступен только через loopback
  и защищён от неподходящих запросов.

Решение пересматривается, если появляются несколько Worker,
удалённые исполнители или нагрузка, которую нельзя надёжно обработать
локальным inbox.
