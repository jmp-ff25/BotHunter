# ADR-0005: Безопасное выполнение действий на площадках вакансий

Статус: принято  
Дата: 2026-08-20

## Context

BotHunter автоматически отправляет отклики и сообщения. Эти действия
необратимы и выполняются через внешнюю площадку и браузерный процесс.

Worker может завершиться после фактического действия, но до записи
результата. Повтор команды в такой ситуации способен создать
дублирующий отклик или сообщение.

Транзакция локальной БД не может атомарно охватить действие
на внешней площадке. Поэтому exactly-once гарантировать невозможно.

## Decision

Использовать следующие инварианты.

### Единый исполнитель действий на площадках вакансий

Automation Orchestrator не вызывает External Action Port напрямую.
Все необратимые отклики и исходящие сообщения на площадках вакансий
выполняет External Action Executor.

Перед вызовом adapter-а Executor обязан:

1. получить через Action Unit of Work Port согласованный snapshot
   policy, лимита, pause-state и idempotency state;
2. передать snapshot в Safety and Policy Guard для чистой доменной
   проверки;
3. условным атомарным commit зарезервировать лимит и сохранить
   idempotency record и intent;
4. отклонить commit и повторить проверку, если snapshot устарел;
5. только после успешного commit вызвать External Action Port.

HH Adapter выполняет уже разрешённое действие и не принимает решений
о policy или допустимости повтора.

Успешный commit intent является точкой начала внешнего действия.
Pause, записанная после этой точки, не отменяет начатое действие
и применяется перед следующим side effect.

### Два уровня idempotency

- command idempotency предотвращает повторное исполнение одной команды;
- business-action deduplication предотвращает повтор одного действия
  для одного внешнего объекта.

### Intent и outcome

Перед внешним side effect сохраняется intent. После наблюдаемого
подтверждения сохраняется outcome.

Если исполнение прервалось между этими точками, outcome считается
`unknown`.

### Reconciliation

Для `unknown` Worker:

1. проверяет наблюдаемое состояние внешней площадки;
2. фиксирует успех, если действие подтверждено;
3. повторяет только доказанно безопасное действие;
4. иначе приостанавливает связанный сценарий и уведомляет владельца.

`unknown` не обрабатывается обычным автоматическим retry.

### Pause checkpoints

Durable pause-state проверяется:

- перед получением новой работы;
- перед началом команды;
- непосредственно перед внешним side effect;
- между безопасными шагами workflow.

Pause гарантирует остановку на ближайшей безопасной контрольной точке,
но не отменяет уже отправленное действие.

### Recovery

Истечение command lease запускает reconciliation, а не безусловный
retry. Heartbeat используется для обнаружения недоступного Worker,
но не доказывает исход внешнего действия.

## Consequences

Положительные последствия:

- снижается риск повторных откликов и сообщений;
- неопределённый результат становится явным состоянием;
- восстановление основывается на наблюдаемом внешнем состоянии;
- владелец получает контроль в неоднозначной ситуации;
- семантика паузы соответствует реальным ограничениям.

Отрицательные последствия:

- workflows должны поддерживать дополнительные состояния;
- adapters должны уметь читать наблюдаемое состояние площадки;
- не каждое действие можно автоматически подтвердить;
- некоторые сценарии потребуют вмешательства владельца;
- тестирование восстановления сложнее обычного happy path.

Формат ключей, точные state machines, retry/backoff и контрольные точки
определяются при проектировании соответствующей функциональности.
